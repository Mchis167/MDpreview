# 📝 Session Log Workflow

Workflow này giúp duy trì bối cảnh làm việc khi thực hiện các task lớn kéo dài qua nhiều session. Mỗi giai đoạn hoặc mỗi ngày làm việc sẽ có một file log riêng để tránh quá tải thông tin trong một file duy nhất.

---

## 🛠️ Các chế độ hoạt động (Sub-commands)

Lệnh `/session-log` chấp nhận các tham số sau:

### 1. `new` — Khởi tạo log mới cho task
Dùng khi vừa bắt đầu một task lớn hoặc bắt đầu một ngày làm việc mới cho task cũ.
*   **Hành động:** 
    *   Xác định tên task (kebab-case).
    *   Tạo file `.agents/session-logs/session-log-{task-name}-{YYYY-MM-DD}.md`.
    *   **Truy vết**: Nếu đã có các file log trước đó của cùng task này, hãy điền link vào mục **🔗 Liên kết**.
    *   Điền sơ bộ trạng thái ban đầu vào mục **🔄 Đang dở**.

### 2. `update` — Cập nhật tiến độ
Dùng sau khi hoàn thành mỗi task nhỏ trong cùng một ngày.
*   **Hành động:**
    *   Tìm file log của ngày hôm nay: `session-log-{task-name}-{YYYY-MM-DD}.md`.
    *   Nếu chưa có file của ngày hôm nay (sang ngày mới), hãy thực hiện như lệnh `new` nhưng link tới file của ngày gần nhất.
    *   **Append** nội dung mới vào các mục: ✅ Đã hoàn thành, ⚠️ Quyết định quan trọng, 🐛 Vấn đề gặp phải.
    *   Cập nhật lại mục **🔄 Đang dở**.

---

## 📋 Template File Session Log

Mọi file log được tạo tại `.agents/session-logs/session-log-{task-name}-{YYYY-MM-DD}.md` sẽ có cấu trúc:

```markdown
# [{Task Name}] Session Log — {YYYY-MM-DD}

## 🔗 Liên kết (Links)
- **Log trước**: [Tên file log cũ hơn](file:///absolute/path/to/previous-log.md) (nếu có)
- **Log kế tiếp**: [Tên file log mới hơn](file:///absolute/path/to/next-log.md) (nếu có)

## 📝 Tổng quan (Overview)
<!-- Mô tả ngắn gọn về mục tiêu và phạm vi của task lớn này hoặc giai đoạn hiện tại -->

## ✅ Đã hoàn thành
- [HH:mm] Mô tả chi tiết các thay đổi + file bị ảnh hưởng

## ⚠️ Quyết định quan trọng
<!-- Lý do chọn approach X thay vì Y — thứ AI mới không thể tự suy ra từ code -->

## 🐛 Vấn đề đã gặp & cách giải quyết
<!-- Lỗi X → fix bằng Y — chỉ ghi những lỗi không hiển nhiên -->

## 🔄 Đang dở / Session tiếp theo bắt đầu từ đây
<!-- Đang làm gì, đến đâu, hướng tiếp theo dự kiến -->
```

## ⚠️ Nguyên tắc quan trọng

1.  **Vị trí lưu trữ**: Luôn nằm trong `.agents/session-logs/`.
2.  **Định dạng tên file**: `session-log-{task-name}-{YYYY-MM-DD}.md`. 
    *   Ví dụ: `session-log-asset-panel-2026-05-15.md`
3.  **Tính liên kết**: Khi tạo file mới cho task cũ, BẮT BUỘC phải cập nhật link "Log kế tiếp" ở file cũ và link "Log trước" ở file mới để tạo thành một chuỗi (linked list).
4.  **Section ⚠️ Quyết định quan trọng**: Đây là phần quan trọng nhất. Hãy ghi lại rõ ràng để AI session sau không phải hỏi lại.
5.  **Ngôn ngữ**: Viết dưới dạng hướng dẫn (instruction) cho AI đời sau đọc.

---
> [!TIP]
> Sử dụng `/session-log update` ngay khi bạn hoàn thành một mốc quan trọng để "checkpoint" kiến thức. Nếu sang ngày mới, hãy dùng `/session-log new` để tách file.
