# 📝 Create New Implementation Plan

Workflow này được sử dụng để khởi tạo một bản kế hoạch chi tiết (Implementation Plan) trước khi thực hiện bất kỳ thay đổi mã nguồn nào. Bản kế hoạch này sẽ là "nguồn sự thật" duy nhất cho quá trình thực thi và kiểm thử.

## 📏 Quy tắc đặt tên và lưu trữ

Mọi bản kế hoạch mới phải tuân thủ các quy tắc sau:

1. **Định dạng tên file:** `[tên-tính-năng]-[yyyy-mm-dd].md` (Ví dụ: `asset-panel-refactor-2026-05-15.md`)
2. **Thư mục lưu trữ:** Tất cả các file `.md` kế hoạch phải được tạo và lưu vào thư mục: 
   `./ImplementPlan/ (run: ls ./ImplementPlan/ to discover files)`

## 📋 Quy trình thực hiện

1. **Khởi tạo:** Tạo một file Markdown mới trong thư mục `ImplementPlan` với tên theo quy tắc trên.
2. **Điền Template:** Sao chép và điền đầy đủ thông tin vào template bên dưới.
3. **Review:** Gửi link file kế hoạch cho User để review và phê duyệt (Approve) trước khi code.
4. **Cập nhật:** Trong quá trình thực hiện, cập nhật trạng thái (Status) và các checkpoint trong file này.

### 4.4 🔴 Race Condition & Stale Data Analysis (Bắt buộc nếu liên quan đến async/timing/event)

> Với mọi logic có thể chạy concurrently hoặc bị ảnh hưởng bởi timing, phải trả lời đủ 4 câu hỏi:

| Câu hỏi | Phân tích | Giải pháp |
|---------|-----------|-----------|
| **Execution order**: Ai chạy trước, ai chạy sau? | ... | ... |
| **Stale data**: Data tại điểm đọc có thể outdated không? | ... | ... |
| **Event timing**: Message/event có thể arrive trước khi receiver sẵn sàng? | ... | ... |
| **In-flight ops**: Có operation đang chạy cần chờ/block không? | ... | ... |

> **Safe patterns:** `requestAnimationFrame` · `isUpdating` flag · version/updateId counter · debounce trailing
>
> *Nếu không có async/timing/event → ghi "N/A — logic synchronous".*

## 6. ✅ Definition of Done (DoD)

> Checklist bắt buộc. Chỉ được đánh dấu DONE khi TẤT CẢ các mục dưới đây được tick.

**Functional:**
- [ ] Feature hoạt động đúng theo yêu cầu đã mô tả ở Section 1
- [ ] Không có regression trên các feature hiện có
- [ ] Edge cases đã được handle (xem Section 7)

**Code Quality:**
- [ ] Code đã được review (self-review hoặc peer review)
- [ ] Không có `console.log` / debug code còn sót
- [ ] Tuân thủ coding conventions của project
- [ ] Không có linting errors
- [ ] Race condition & stale data đã được phân tích (Section 4.4) và giải pháp đã implement

**Testing:**
- [ ] Unit tests đã pass
- [ ] Integration tests đã pass (nếu có)
- [ ] Manual test cases đã pass (xem Section 7)

**Documentation:**
- [ ] Inline comments cho logic phức tạp
- [ ] README / docs cập nhật nếu cần
- [ ] CHANGELOG cập nhật (nếu project có dùng)
